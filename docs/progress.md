## M4 — 문자 붙여넣기, 카테고리 자동 추천 (배포, 실제 문자 테스트 대기)

### 한 일
- 카테고리 자동 추천(F-16): `merchant_rules` 테이블 + 내역 저장 시 DB 트리거가 가맹점 → 카테고리 규칙을 기억. 추천 순서: 기억한 규칙 → 키워드 사전(SPEC §8.1) → 기타. 직접 입력에서 가맹점을 쓰면 카테고리가 자동으로 골라지고, 직접 고르면 덮어쓰지 않음. 저장 직후 화면에서도 바로 기억(서버 새로고침을 기다리지 않음)
- 문자 인식기(F-15, `lib/sms/`): 나누기, 금액(누적·잔액·한도 건너뜀), 날짜(MM/DD, MM.DD, M월 D일, 작년 판단), 시간, 입금/출금, 취소, 카드사 추정, 가맹점
  - SPEC 규칙 보완: 날짜·시간과 가맹점이 같은 줄(예: `09/26 19:20 이마트`)이면 날짜·시간만 지우고 가맹점으로 씀. "하나로마트"처럼 카드사 이름으로 시작하는 가맹점은 카드 줄로 보지 않음
- 결제수단 연결: 결제수단의 문자 인식용 별칭과 대조(가장 긴 별칭 우선). 없으면 카드사 추정만 표시하고 사용자가 고름
- 문자로 추가 화면: 패널 탭(직접 입력/문자로 추가), 미리보기 행마다 체크·날짜·금액·가맹점·카테고리·결제수단·구분·사람 수정, 중복 경고(±1일·같은 금액·같은 가맹점, 기본 해제), 취소 문자 배지(환불로 기록, 기본 해제), N건 한 번에 저장(전부 저장되거나 하나도 안 됨)
- 확인: 단위 테스트 126개, E2E 10개 통과. 폰 크기 화면 확인. 테스트 데이터 삭제

## M3 — 홈 대시보드, 정기지출·납부 체크, E2E (완료 2026-09-27, 폰 확인함) → MVP 완료, 실사용 시작

### 한 일
- DB: `recurring_items`(중지는 `end_month`), 내역에 정기지출 연결(같은 항목·같은 달 하나만), 체크·해제 함수(`check_recurring`, `uncheck_recurring`), RLS, 실시간
- 정기지출 화면(F-30, F-31): 이번 달 납부 체크리스트(상태: 납부 완료/오늘/○일 후/○일 지남), "매달 금액이 달라요"는 체크할 때 금액 입력(기본값 지난 납부 금액), 체크 해제 + 되돌리기, 등록·수정·중지·다시 시작, 요약 "2/3 납부 · …원 냈고 …원 남았어요"
- 미납 배지: 결제일이 오늘이거나 지난 미납 개수 (사이드바·탭바)
- 홈 대시보드(F-20): 사람 필터, 이번 달 지출(큰 숫자) + 지난달 같은 기간 비교, 공동/A/B 분할 막대(합 100% 보정), 수입·수입−지출, 이번 달 정기지출, 최근 내역 6건
- 최근 활동 한 줄(F-14): "서연님이 오늘 다이소 12,000원을 추가했어요"
- E2E(Playwright, `pnpm test:e2e`): 로그인 막기, 내역 추가·삭제·되돌리기, 두 사람 실시간, 사람 필터, 정기지출 등록→체크→홈 반영→해제, 모바일 탭바. 이 PC의 Chrome 사용, 테스트 계정은 자동 생성·삭제
- 확인: 단위 테스트 89개, E2E 8개, 정기지출 권한·함수 17개 통과. 샘플 데이터로 홈 숫자 직접 계산해 대조. 테스트 데이터 삭제

### 속도 개선 (사용자 피드백: "월세 체크가 느려 보여요")
- 원인: Vercel 함수가 미국 워싱턴(iad1), DB는 서울 → DB 왕복마다 약 0.2초, 체크 한 번에 왕복 여러 번
- `vercel.json`으로 함수 지역을 서울(icn1)로. 로그인 화면 응답 중간값 350ms → 176ms (DB를 쓰는 화면은 더 크게 줄어듦)
- 구성원 확인을 `getUser`(네트워크) → `getClaims`(ES256 서명 로컬 검증)로 바꿔 왕복 1번 줄임
- 정기지출 체크는 누르는 즉시 화면에 반영(낙관적 업데이트), 실패하면 되돌리고 알림. 내역 삭제 시 패널 바로 닫힘

### 결정한 것
- 미납 배지 기준: 결제일이 오늘이거나 지난 미납 (A안, SPEC 반영)
- E2E는 M3에서 도입 (A안)
- 중지는 `is_active` 대신 `end_month`(중지한 달)로 기록, "다시 시작" 가능 (SPEC 반영)
