# 앱 단순화 + 내역 ↔ 자산 연결 설계

날짜: 2026-10-25 · 상태: 사용자 승인 (대화에서 1/3·2/3·3/3 단계별 확인)

## 목적

기능이 너무 많아 쓰기 번거롭다. **내역(지출·수입) + 통계 + 자산(얼마 있는지)** 만 남기고, 지출·수입을 기록할 때 자산을 골라 그 자산 잔액이 바뀌게 하면 돈 관리는 충분하다 (사용자, 2026-10-25).

잘 됐다고 볼 기준: 내역에 "생활비통장에서 12,000원 지출"을 넣으면 자산 화면의 생활비통장 잔액이 바로 12,000원 줄고, 두 사람 폰에서 똑같이 보인다.

## 사용자 결정

| 질문 | 결정 |
| --- | --- |
| 카드로 쓴 돈 | 결제수단을 없애고 자산을 바로 고른다. 카드는 부채 자산으로, 카드값 납부는 통장 → 카드 이체 |
| 이미 입력한 내역 61건 | 자산 연결 없이 둔다. 자산마다 지금 금액(최근 기록)부터 시작 |
| 자산 화면 | 순자산 + 자산·부채 목록만. 저축 목표·순자산 추이는 뺀다 |
| 통계 | 6개월 지출 그래프 + 카테고리별(지난달 대비) + 사람별. 월말 결산은 뺀다 |
| 잔액 계산 | 잔액 기록 + 그 뒤 내역으로 매번 계산 (DB에 잔액을 따로 고쳐 두지 않음) |
| 공휴일 | 남긴다 (한 달 기준 F-56이 쓴다) |

## 1. 남는 것과 빠지는 것

**남는 화면**
- 홈: 이번 달 수입·지출 요약, 지난달 비교, 최근 내역, 오늘 기분, 사람 필터
- 내역: 입력·목록·달력·검색. 결제수단 대신 자산, 종류에 이체 추가
- 통계: 6개월 지출 그래프, 카테고리별(지난달 대비), 사람별
- 자산: 순자산, 자산·부채 목록(잔액), 잔액 맞추기
- 설정: 프로필(사진), 가구·초대, 카테고리, 한 달 기준, 공휴일, 휴대폰 알림, 화면 모드, 앱 설치, 서비스 사용량

**빠지는 것**: 일정(F-19), 메모(F-18), 대출(F-43), 정기지출(F-30·F-31), 예산(F-21·F-22, 카테고리·통장카드), 월말 결산(F-25), 문자 인식(M4), 엑셀 내보내기(F-52), 저축 목표(F-42), 순자산 추이, 자산 구성 도넛, 결제수단(설정 → 계좌·카드, 사이드바 "함께 보는 계좌·카드").

**메뉴**: 폰 탭바 홈 · 내역 · 통계 · 자산 · 설정. 웹 사이드바 홈 · 내역 · 통계 · 자산. 사이드바 아래 아바타·접속 상태·알림 종·동기화 표시는 그대로.

**남는 연결 기능**: 알림(앱·휴대폰) — 내역 추가·수정·삭제·되돌리기와 기분만. 실시간 동기화, Supabase 깨우기(F-54), 가맹점 → 카테고리 자동 선택(`merchant_rules`).

## 2. 데이터와 잔액 계산

**내역 (`transactions`)**
- `type`: `expense` · `income` · `transfer`
- `asset_id`: 지출·수입의 자산, 이체의 보내는 자산. `to_asset_id`: 이체의 받는 자산 (이체에만)
- 새로 넣는 지출·수입은 자산 필수 (서버 액션 검증). DB는 null 허용 — 예전 내역 61건은 "자산 없음"으로 남고, 고칠 때 비워 둬도 저장된다
- 이체: 카테고리 없음(`category_id` null 허용, 이체일 때만), 보내는·받는 자산 필수, 둘이 같으면 안 됨. 수입·지출 합계·통계·달력 합계에서 뺀다
- 공동/개인·사람 기본값은 자산 소유(`assets.owner`)로 정한다 (지금 결제수단이 하던 것과 같음, 바꿀 수 있음). 이체도 구분·사람 칸은 둔다(누가 옮겼는지)
- DB 트리거가 자산이 같은 가구인지, 유형별 필수 칸, 보내는 ≠ 받는 자산을 확인한다
- `payment_method_id` 칸과 `payment_methods` 표는 지운다 (지우기 전에 백업)

**잔액 계산** (`lib/calc/assets.ts`, 순수 함수 + 단위 테스트)
- 자산마다 가장 최근 잔액 기록 R(`asset_values`: `as_of`, `amount`, `created_at`, 지운 것 제외)에서 시작
- 반영하는 내역: 지우지 않은 것 중 `occurred_on > R.as_of`, 또는 `occurred_on = R.as_of` 이고 `created_at > R.created_at`
- 자산(`is_liability = false`): 수입 +, 지출 −, 이체로 받으면 +, 보내면 −
- 부채(`is_liability = true`): 지출 +, 수입 −, 이체로 받으면 −(갚음), 보내면 +
- 결과가 0보다 작을 수 있다 → `-30,000원`처럼 그대로 표시 (기록 자체는 지금처럼 0 이상)
- 순자산 = 자산 잔액 합 − 부채 잔액 합
- 기록이 없는 자산은 없다 (만들 때 금액·기준일 필수, 기록은 하나 이상 남아야 함 — 지금 규칙 유지)

**잔액 맞추기**: 지금의 "금액 기록 추가"를 이름만 바꾼다. 기본 오늘, 지난 날짜 가능, 같은 날짜면 금액만 바뀜, 기록 목록·삭제·되돌리기 유지.

**지운 자산**: 목록·고르기 창에서 숨긴다. 예전 내역에는 이름이 보인다 (soft delete라 이름을 읽을 수 있음).

**DB 마이그레이션 (PR마다 하나)**
- 지우기 전에 해당 표 데이터 전부를 로컬 `tmp/`(gitignore)에 JSON으로 백업
- 지우는 표: `notes`, `events`, `loan_profiles`, `loan_debts`, `loan_scenarios`, `recurring_items`, `budgets`, `budget_months`, `spend_budgets`, `spend_budget_methods`, `spend_budget_amounts`, `goals`, `goal_contributions`, `payment_methods`, 그리고 관련 함수·트리거
- `notifications`: `note_id`·`event_id` 칸 삭제, 메모·일정·정기지출 알림 행 삭제, `kind` 검사를 `created, updated, deleted, restored, mood_set`으로
- `transactions`: `recurring_item_id`, `recurring_month`, `payment_method_id` 삭제, `asset_id`·`to_asset_id` 추가, `type`·`category_id` 규칙 변경
- `households.period_*`, `period_overrides`, 공휴일 표, `moods`, `push_subscriptions`, `asset_values`, `assets`, `merchant_rules`는 유지
- 변경 뒤 `pnpm db:types`

## 3. 화면

**내역 입력 창**: 위에 지출 · 수입 · 이체. 지출·수입은 결제수단 자리에 자산 고르기(자산 / 부채 묶음, 이름 옆에 지금 잔액 `생활비통장 1,234,000원`). 이체는 금액, 날짜, 보내는 자산, 받는 자산, 메모.

**내역 목록**: 이체 줄은 "생활비통장 → 현대카드 500,000원"(금액 `ink-muted`, +/− 없음). 결제수단 필터 → 자산 필터(이 자산이 들어간 이체 포함), 유형 필터에 이체.

**자산 화면**: 순자산(`amount-hero`), 자산·부채 목록(종류별 묶음, 잔액, "10월 24일 기록 + 내역 3건"). 누르면 잔액 맞추기, 기록 목록, "이 자산 내역 보기"(`/transactions?asset=<id>`).

**사이드바**: "계좌·카드" 자리에 자산 목록 + 잔액 (접기 가능, 지금 접기 동작 재사용).

**홈**: 수입·지출 요약, 최근 내역, 오늘 기분. 예산 카드·정기지출 체크 목록 제거.

**통계**: 예산·사용률 칸, 예산 없는 고정지출 칸, 월말 결산 링크 제거.

**알림 문장**: 이체는 "서연님이 생활비통장 → 현대카드 500,000원 이체를 추가했어요".

## 4. 확인

- 단위 테스트: 잔액 계산(자산·부채 × 지출·수입·이체, 같은 날 기록 전·후 내역, 지운 내역, 마이너스, 지운 자산), 합계·통계에서 이체 제외, 입력 검증(이체 자산 둘 필수·서로 다름, 새 지출·수입 자산 필수)
- E2E: 지출 → 잔액 감소, 이체 → 양쪽 바뀜, 잔액 맞추기 뒤부터 다시 계산, 자산 필터. 빠진 기능의 E2E는 지운다
- DB 권한: 다른 가구 자산으로 내역 저장 불가, 이체 규칙 위반 거부
- PC·폰 폭 화면 직접 확인 (E2E 계정)
- `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:e2e`
