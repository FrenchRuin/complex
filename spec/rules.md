# 계산·기본 카테고리·상세 규칙 (§6~8)

> `SPEC.md`(목차)의 일부. 원래 절 번호를 그대로 둔다.

## 6. 계산 규칙

- **월 경계**: KST 기준 1일 00:00 ~ 말일 23:59.
- **지출 합계**: `type = 'expense'`, `deleted_at is null`.
- **사람 필터**:
  - 공동 = `scope = 'joint'`
  - A = `scope = 'personal' and member_slot = 'a'`
  - 전체 = 모두
- **분할 막대 비율**: 공동 / A 개인 / B 개인 지출 합계의 비율. 반올림 후 합이 100이 되도록 가장 큰 값에서 보정.
- **짧은 금액 표기**(캘린더·그래프): 1만 이상은 만 단위 소수 첫째 자리(`8.7만`, `10만`), 1만 미만은 쉼표(`8,500`).

## 8. 상세 규칙

### 8.1 카드 문자 인식 (F-15, 2차)

- **나누기**: 빈 줄 또는 `[Web발신]`을 기준으로 문자 단위로 나눈다. `원`이 붙은 금액이 없는 조각은 버린다.
- **금액**: 첫 번째 `숫자(쉼표 포함)+원`. 앞에 "누적", "잔액", "한도"가 붙은 금액은 건너뛴다.
- **날짜**: `MM/DD`, `MM.DD`, `MM-DD`, `M월 D일`. 연도는 올해, 단 인식한 월이 이번 달보다 2개월 이상 뒤면 작년. 없으면 오늘.
- **시간**: `HH:MM`.
- **유형**: "입금"이 있고 "출금"이 없으면 수입, 그 외 지출. "취소"가 있으면 취소 문자.
- **결제수단**: 결제수단의 `sms_aliases`와 먼저 대조. 없으면 카드사 이름 목록(신한, 삼성, 현대, KB국민, 국민, 롯데, 하나, 우리, BC, NH농협, 카카오뱅크, 토스, IBK)으로 추정해 표시만 하고, 저장 전 사용자가 결제수단을 고른다.
- **가맹점**: 금액·날짜·시간·카드명·"승인/일시불/할부/누적/잔액"·마스킹된 이름(`김*수`)이 들어간 줄을 제외한 마지막 줄. 한 줄짜리 문자는 시간 뒤 텍스트에서 "누적/잔액" 전까지.
- **카테고리 추천 순서**: `merchant_rules` → 키워드 사전 → 기타.
  - 키워드 사전 예: 스타벅스·투썸·이디야·메가커피·빽다방·컴포즈·파리바게뜨 → 카페·간식 / 배달의민족·배민·요기요·쿠팡이츠 → 배달 / 이마트·홈플러스·롯데마트·코스트코·GS25·CU·세븐일레븐·다이소·컬리 → 생활·마트 / 카카오T·택시·티머니·코레일·SRT·주유 → 교통 / 쿠팡·11번가·G마켓·무신사 → 쇼핑 / 약국·병원·의원·치과 → 의료 / CGV·메가박스·롯데시네마 → 데이트·여가 / 넷플릭스·유튜브·티빙·웨이브 → 구독
- **구분·결제한 사람 기본값**: 결제수단 소유가 공동이면 공동 + 입력한 사람, A/B 소유면 개인 + 그 사람.
- 파서는 순수 함수로 만들고, 실제 문자 예시로 단위 테스트를 둔다(`fixtures/sms/*.txt`).

### 8.2 엑셀/CSV 가져오기 — **제외됨** (2026-09-27 사용자 결정)

카드사·은행 이용내역 파일 가져오기는 하지 않기로 했다. 필요해지면 git 기록의 이전 SPEC(열 매핑·카테고리/결제수단 매핑·미리보기·배치 되돌리기 설계)을 참고해 다시 계획한다.
DB의 `transactions.source` 값 목록에 남아 있는 `'import'`는 쓰지 않는다.

### 8.3 CSV 형식 (내보내기)

열 순서: `날짜, 시간, 유형, 카테고리, 가맹점, 메모, 금액, 결제수단, 구분, 사람`
- 유형: 지출/수입, 구분: 공동/개인, 사람: 표시 이름, 금액: 쉼표 없는 정수.
